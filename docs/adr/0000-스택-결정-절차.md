# ADR-0000: 기술 선택을 정하는 절차

- 상태: 초안
- 날짜: 2026-11-04

## 맥락

후보 스택(Next.js, TanStack Query, Zustand, shadcn/ui, ECharts, Vercel AI SDK, Zod, Vitest, Playwright, PostgreSQL)은 근거 없이 모은 목록이다. 근거 없이 고르면 "왜 이걸 골랐나"에 답할 수 없고, 나중에 바꿀 때 무엇을 잃는지도 알 수 없다.

## 결정

기술 하나를 정할 때마다 `docs/adr/NNNN-제목.md`를 쓰고, 아래 항목을 모두 채운 뒤에만 `package.json`에 추가한다.

1. **풀려는 문제**: 이 프로젝트의 어떤 요구를 위한 선택인가
2. **후보 2개 이상**: "라이브러리 없이 직접"도 후보로 넣는다
3. **비교 근거**: 공식 문서 링크, 또는 이 저장소에서 잰 실측(Profiler 수치, 번들 크기, 코드 줄 수)
4. **고른 것과 이유**: 3번 근거에서 나온 이유만 쓴다
5. **버린 대안과 그 대안의 가장 강한 장점**: 버린 쪽이 이기는 조건도 적는다
6. **되돌리는 비용**: 나중에 바꾸려면 무엇을 고쳐야 하는가

## 적용 규칙

- 직접 구현이 가능한 주제(스트림 파서, 가상 리스트, 에이전트 루프)는 라이브러리 없는 구현을 먼저 만들고 그것을 비교 대상 1번으로 둔다
- 익숙한 도구(차트, UI 컴포넌트, 서버 상태 캐시)도 ADR은 쓴다. 비교 근거는 공식 문서 확인으로 충분하다
- 기각한 대안의 가장 강한 반론을 최소 2개 적는다
- 라이선스(MIT 또는 Apache-2.0)도 이 절차로 정한다

## 버린 대안

- **후보 목록을 그대로 채택**: 가장 빠르다. 하지만 선택 근거를 설명할 수 없다
- **착수 시점에 스택을 한꺼번에 결정**: 결정이 한곳에 모인다. 하지만 직접 구현을 해 보기 전이라 비교 근거가 없다

## 결과

- 스택이 기능 단위로 하나씩 정해지므로 초기 설정이 늦어진다. 대신 각 선택의 이유가 저장소에 남는다
- ADR 없이 추가된 의존성은 리뷰에서 막는다
