# ADR-0003: 접근성 컴포넌트 라이브러리와 스타일 방식

- 상태: 채택
- 날짜: 2026-11-09

## 풀려는 문제

장애 화면에 셀렉트(시나리오), 단일 선택 버튼 묶음(배속), 여러 개를 켜고 끄는 필터 칩(심각도·서비스), 스위치(지표 숨기기), 툴팁이 필요했다(툴팁은 뒤에 뺐다. 아래 "에이전트 접근성"). 지금까지는 브라우저 기본 `<select>`·체크박스를 썼고, 모양을 맞출 수 없었다. 직접 만들면 키보드 조작(화살표 이동, Home/End, Esc), 팝오버 위치 계산, 스크린 리더용 역할·상태 속성을 컴포넌트마다 구현해야 한다. 이 프로젝트가 보여 주려는 것은 스트림 처리·차트·승인 흐름이라, 이 부분은 검증된 구현을 쓰고 모양만 직접 입힌다.

## 후보

| 후보 | 버전·라이선스 (npm 레지스트리, 2026-11-09 확인) |
|---|---|
| A. 라이브러리 없이 | 네이티브 `<select>`·`<input type="checkbox">` + `aria-pressed` 버튼 |
| B. React Aria Components | `react-aria-components` 1.22.1, Apache-2.0 |
| C. Radix Primitives | `radix-ui` 1.8.1(개별 패키지 묶음), MIT |
| D. Base UI | `@base-ui/react` 1.9.0, MIT |

## 판단 기준

1. WAI-ARIA Authoring Practices Guide(APG)의 패턴 항목을 얼마나 충족하는가. 역할·상태 속성과 키보드 동작을 렌더 결과로 확인한다
2. 번들 크기
3. 스타일을 입히는 방식

공식 문서의 "접근성을 지원한다"는 문장은 기준으로 쓰지 않았다. 네 후보 모두 같은 주장을 하므로 차이를 만들지 못한다.

## 비교 결과

### APG 충족 (B·C 실측)

B 와 C 로 배속 묶음과 필터 칩을 같은 조건(값 3개, 레이블 있음)으로 그려 비교했다. 역할·속성은 렌더된 DOM 에서 읽었다. 키보드 동작은 jsdom 에서 키 이벤트로 확인하고 라이브러리 소스로 교차 확인했다. jsdom 에서 재현되지 않은 항목은 소스로만 확인했고, 표에 그렇게 적었다. D 는 이 비교를 하지 않았다.

배속 묶음 (APG Radio Group 패턴)

| 항목 | B. React Aria | C. Radix |
|---|---|---|
| 묶음 `radiogroup`, 항목 `radio`, `aria-checked`, 레이블 | 충족 | 충족 |
| Tab 으로 들어오면 선택된 항목에 포커스 | 미충족. 첫 진입은 첫 항목 (소스 확인) | 충족 |
| 화살표로 다음·이전 항목 이동 | 충족 | 충족 |
| 마지막에서 처음으로 순환 | 미충족. 끝에서 멈춤 (`useToolbar` 가 wrap 없이 `focusNext()` 호출) | 충족 (`loop` 기본값 true) |
| 화살표로 옮기면 선택도 바뀜 | 미충족 | 미충족 (선택은 누를 때만) |

필터 칩 (APG Toolbar 패턴 + toggle button)

| 항목 | B. React Aria | C. Radix |
|---|---|---|
| 묶음 `toolbar`, 항목 `aria-pressed`, 레이블 | 충족 | 충족 |
| 화살표 이동, Tab 한 번으로 묶음 밖으로 | 충족 | 충족 |
| Home/End (APG 선택 항목) | 없음 | 있음 |

C 가 두 항목에서 앞섰고 B 가 앞선 항목은 없었다. 두 후보 모두 "화살표로 옮기면 선택도 바뀜"을 하지 않아, 래퍼(`Segmented`)에 직접 넣었다. 이동 키(화살표·Home·End)를 누른 직후의 포커스에서만 선택한다. 포커스만으로 선택하면 마우스를 누르는 순간(브라우저가 포커스를 먼저 준다) 선택돼 끌어서 취소할 수 없고, 배속이 바뀔 때마다 스트림을 처음부터 다시 받기 때문이다.

### 번들 크기 (실측)

저장소 밖 임시 프로젝트에서 같은 4종(셀렉트, 다중 선택 토글 그룹, 스위치, 툴팁)을 각 라이브러리로 하나씩 그리고 Vite 8.3.6 으로 빌드했다. React·ReactDOM 은 따로 떼어 냈다. C 와 D 는 floating-ui 를 공유하므로 그 청크(22.01 kB, gzip 8.60 kB)를 각각에 더했다.

| 후보 | 크기 | gzip |
|---|---|---|
| C. Radix | 108.8 kB | 37.3 kB |
| D. Base UI | 164.9 kB | 57.9 kB |
| B. React Aria | 197.7 kB | 64.1 kB |

B 의 청크에는 34개 언어의 컴포넌트 문구가 함께 들어간다(번들에서 언어 코드 34종 확인).

### 스타일 입히기 (공식 문서)

- B 는 상태를 컴포넌트마다 같은 이름의 data 속성(`data-selected`, `data-focus-visible`, `data-hovered`)으로 내보낸다 (https://react-spectrum.adobe.com/react-aria/styling.html)
- C 는 상태를 `data-state` 하나에 담고 값이 컴포넌트마다 다르다(토글 항목 `on`/`off`, 스위치 `checked`/`unchecked`, 셀렉트 옵션 `checked`). 포커스 상태 속성은 없어 키보드 포커스는 CSS `:focus-visible` 로 잡는다 (https://www.radix-ui.com/primitives/docs/components/toggle-group)

이 차이는 CSS 선택자 몇 줄의 차이라 결정에 크게 반영하지 않았다.

### A (라이브러리 없이)

네이티브 `<select>` 는 열린 목록의 모양을 바꿀 수 없다. 처음에는 시나리오 설명을 옵션 아래에 보여 주려 했지만, 설명에 정답이 들어 있어 뺐다(아래 "정답 노출"). 그래서 셀렉트만 놓고 보면 A 를 버린 이유는 목록 모양뿐이다. 칩·세그먼트의 묶음 안 화살표 이동(roving tabindex)은 직접 구현해야 한다.

## 고른 것과 이유

C. Radix Primitives. APG 비교에서 B 보다 두 항목 앞섰고, 4종 기준 gzip 26.8 kB 가볍다.

설치는 쓰는 3개만 개별 패키지로 한다: `@radix-ui/react-select` 2.4.1, `@radix-ui/react-toggle-group` 1.2.1, `@radix-ui/react-switch` 1.4.1 (모두 `radix-ui` 1.8.1 이 묶은 버전, exact 고정). 묶음 패키지 `radix-ui` 는 쓰지 않는 primitive 까지 설치해 새 패키지가 74개였고, 개별 설치는 43개(MIT 42, 0BSD 1)다. 빌드 결과 크기는 같았다.

이 저장소의 본 화면 JS 는 263.04 kB(gzip 82.36 kB)에서 385.07 kB(gzip 123.07 kB)로 늘었다. 늘어난 양에는 이번에 새로 쓴 화면 코드(차트·카드 등)도 들어 있다. 같은 화면을 B 로 만들었을 때는 477.58 kB(gzip 150.23 kB)였다.

표(서비스 상태)와 카드·뱃지는 동작이 없어 HTML 로 직접 만들었다.

## 스타일 방식

| 후보 | 내용 |
|---|---|
| ㄱ. CSS 변수 토큰 + CSS Modules | 의존성 0. Vite 가 `*.module.css` 를 기본 지원 (https://vite.dev/guide/features#css-modules) |
| ㄴ. Tailwind CSS | 유틸리티 클래스. `data-[state=on]:` 같은 변형으로 상태를 읽을 수 있다 |

ㄱ 을 골랐다. 토큰(색·간격·글자·모서리·그림자)은 `src/web/tokens.css` 한 파일에 CSS 변수로 두고, 컴포넌트 CSS 는 이 변수만 읽는다. 화면 규모(컴포넌트 8개 안팎)에서는 새 의존성과 빌드 설정을 들일 이유가 없다.

ㄴ 이 이기는 조건: 화면이 수십 개로 늘거나 여러 사람이 함께 고쳐 클래스 이름 짓기와 CSS 파일 관리가 부담이 될 때.

## 버린 대안과 그 대안의 가장 강한 장점

- **B. React Aria**: 상태 속성 이름이 컴포넌트마다 같아 스타일 코드가 가장 짧고, 폼 검증·날짜 선택 같은 큰 컴포넌트까지 같은 방식으로 갖춰져 있다. 이후 화면에 그런 컴포넌트가 많이 필요해지면 B 가 이긴다
- **D. Base UI**: 공식 문서 예제가 CSS Modules 로 쓰여 있어(https://base-ui.com/react/components/toggle-group) 이 저장소의 스타일 방식과 가장 가깝다. APG 비교를 하지 않았으므로, C 에서 문제가 생기면 먼저 같은 방법으로 비교할 후보다
- **A. 라이브러리 없이**: 의존성이 0 이고 번들이 가장 작다. 컨트롤이 셀렉트 하나와 체크박스 하나뿐이었다면 A 가 이긴다

## 에이전트 접근성

라이브러리를 고를 때는 기준에 없었고, 고른 뒤 따로 확인했다. 브라우저 에이전트는 대부분 DOM 이나 접근성 트리를 읽어 역할과 이름으로 요소를 찾고, 값은 글자로 읽는다. APG 를 맞추면 상당 부분이 같이 충족되지만, 사람은 눈으로 보고 에이전트는 못 보는 정보가 남는다.

이 기준은 B 와 C 를 가르지 못한다. 둘 다 셀렉트 목록과 툴팁을 열 때만 DOM 에 만든다. 셀렉트만 보면 옵션이 늘 DOM 에 있는 네이티브 `<select>`(A) 가 에이전트에게 가장 낫다.

브라우저에서 DOM 을 읽어 확인한 것과 이번에 고친 것

| 항목 | 상태 |
|---|---|
| 조작 요소의 역할과 이름 | 23개 모두 있음 (`combobox: 시나리오`, `radio: 5x`, `switch: 지표 숨기기` 등) |
| 경보 값 | 카드 글자로 읽힘 ("p99 2,715ms / 기준 500ms 기준의 5.4배 직전 배포 v1.4.2") |
| 차트 값 | SVG 대신 `#timeline-summary` 글자로 배포·경보·서비스별 최대값을 읽음 |
| 필터 칩 이름 | 보이는 글자를 이어 붙이면 "에러9" 로 읽혔다. 이름은 라벨("에러")로 고정하고 건수는 설명("9건")으로 붙였다. 건수를 이름에 넣으면 이벤트가 올 때마다 이름이 바뀌어 이름으로 버튼을 찾는 에이전트가 놓친다 |
| 칩 건수 | "그 칩을 켜면 목록에 몇 건이 보이나" 로 맞췄다. 심각도 건수는 서비스 필터를, 서비스 건수는 심각도 필터를 반영한다. 전에는 "에러 9건" 인데 목록에 3건만 보일 수 있었다 |
| 연결 상태 | 툴팁에만 있던 설명을 뱃지 안 숨김 글자로 늘 둔다(`실시간. SSE 로 이벤트를 받는 중입니다`). `role="status"` 에 두어 바뀔 때 스크린 리더가 읽게 했다(실제 낭독은 확인 전) |
| 툴팁 | 뺐다. 유일한 사용처(연결 뱃지)의 트리거가 `role="button"` 인데 누르면 아무 일도 없어 사람과 에이전트를 헷갈리게 했고, 내용은 숨김 글자와 겹쳤다. 마우스는 `title` 로 본다. `@radix-ui/react-tooltip` 의존성도 뺐다 |
| 화면 상태 | 시나리오·배속·지표 표시·필터를 URL 쿼리로 주고받는다(`src/web/urlState.ts`). 클릭 없이 원하는 상태로 바로 열 수 있다. 같은 키 반복과 쉼표 목록을 모두 받고, 모르는 쿼리·`#해시` 는 보존한다. 아직 나타나지 않은 서비스의 숨김은 칩을 눌러도 지워지지 않는다 |
| 빈 목록 안내 | 지표만 들어와 비었을 때 "필터 초기화"(눌러도 그대로)를 안내하던 것을 "지표 이벤트 보이기"로 고쳤다 |
| 강제 색상 모드 | 포커스 링이 `box-shadow` 뿐이라 Windows 고대비에서 사라졌다. 투명 `outline` 을 함께 두고, 선택된 배속·스위치·옵션은 선으로 그린다. 고대비 화면에서 직접 보지는 않았다 |

남는 한계

- **이벤트 목록은 보이는 줄만 DOM 에 있다**(ADR-0002 가상화). 전체 건수는 `aria-rowcount` 로 알 수 있지만 내용을 다 읽으려면 스크롤해야 한다. 이벤트 전체가 필요한 에이전트는 화면 대신 SSE `/events` 를 직접 읽는 것이 맞는 경로다(`src/server/sse.ts`). 화면이 받는 것과 같은 이벤트가 같은 순서로 온다. 화면은 이 값을 `src/events/schema.ts` 검증기에 통과시킨 뒤에 쓰므로, 직접 읽는 쪽도 같은 검증을 거쳐야 한다
- **셀렉트의 옵션은 열어야 DOM 에 생긴다.** 쓸 수 있는 값은 URL 쿼리 설명(`src/web/urlState.ts` 머리 주석)과 서버 `/scenarios` 로도 알 수 있다
- **라벨 "시나리오" 를 클릭했을 때 동작이 한결같지 않다.** Radix Select 는 포인터 종류 초깃값이 터치라, 처음 라벨 클릭은 목록을 열고 버튼을 한 번 마우스로 누른 뒤에는 포커스만 준다

## 정답 노출

시나리오 파일(`scenarios/*.json`)에는 정답(`rootCause`)과 원인을 문장으로 적은 설명(`description`)이 있다. 이 시나리오로 운영자와 에이전트의 원인 찾기를 잰다(README 로드맵 v0.2). 처음 구현은 설명을 셀렉트 옵션 아래에 보여 줬고, 에이전트 접근성을 손보며 현재 값의 설명을 늘 DOM 에 두기까지 했다. 화면을 여는 순간 답이 보이는 구조였다. 리뷰에서 잡혔다.

- 화면에서 설명을 뺐다. 셀렉트는 시나리오 이름만 보여 준다
- 본 화면은 시나리오 파일에서 이름·시작 시각·길이만 가져온다(이름 붙은 JSON 가져오기). 측정 페이지(`Bench.tsx`)는 시뮬레이터를 돌리느라 파일 전체가 필요해 `?raw` 로 따로 읽는다. 같은 JSON 모듈을 둘이 함께 쓰면 공유 모듈이 본 화면 청크로 올라가 정답이 본 화면 번들에 들어가기 때문이다
- 확인: 빌드 결과 본 화면 청크에서 `rootCause`·`capacityFactor`·설명 문장("처리 용량") 검색 0건. `/?bench` 로 열 때만 받는 측정 청크에는 남아 있다. 화면 JS 를 직접 뒤지는 쪽까지 막으려면 측정 페이지를 별도 빌드로 빼야 한다

## 남은 문제

- **실제 스크린 리더로 들어 보지 않았다.** APG 충족은 역할·속성·키보드가 명세대로라는 뜻이고, VoiceOver 등이 어떻게 읽는지는 따로 확인해야 한다
- **셀렉트·스위치는 B 와 비교하지 않았다.** C 로 바꾼 뒤 브라우저에서 확인한 것: 셀렉트가 ArrowDown 으로 열리고 Esc 로 닫히며 포커스가 버튼으로 돌아온다, 스위치가 `role="switch"` 와 `aria-checked` 를 갖고 글자를 눌러도 켜진다

## 되돌리는 비용

라이브러리를 쓰는 곳은 `src/web/ui/controls.tsx` 한 파일이다. 화면 코드는 이 파일의 `Select`·`Segmented`·`ChipGroup`·`Switch` 만 부른다. 다른 후보로 바꾸면 이 파일과 `controls.module.css` 의 상태 선택자(`[data-state='on']` 등)를 고치면 된다. 이번에 B 에서 C 로 실제로 바꿨을 때 고친 코드도 이 두 파일과 `package.json` 이었다.
