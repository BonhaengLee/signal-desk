# ADR-0005: 감사 로그와 승인 상태 저장소

- 상태: 채택
- 날짜: 2026-11-09

## 풀려는 문제

에이전트가 제안한 조치(배포 되돌리기, 담당자 호출)는 사람이 승인해야 실행된다. 누가 언제 무엇을 보고 승인·거절했는지 나중에 확인할 수 있어야 하고, 기록은 고쳐지면 안 된다. 승인 버튼을 두 사람이 동시에 눌러도 결정은 하나만 남아야 한다. 서버를 다시 켜도 기록이 남아야 한다.

## 후보

| 후보 | 내용 |
|---|---|
| A. 메모리 | 배열과 Map. 서버를 끄면 사라진다 |
| B. JSON Lines 파일 | 한 줄에 이벤트 하나씩 추가 |
| C. SQLite (Node 내장 `node:sqlite`) | 의존성 0. 파일 하나 |
| D. PostgreSQL | DB 서버와 드라이버(`pg`) 필요. 테스트·CI 에도 DB 를 띄워야 한다 |

## 비교 근거

- B 는 추가는 쉽지만 "pending 일 때만 approved 로" 같은 조건부 변경을 파일 잠금 없이 원자적으로 할 수 없다
- C·D 는 `UPDATE proposals SET status = ? WHERE id = ? AND status = 'pending'` 한 문장으로 조건부 변경을 하고, 바뀐 행 수(1 또는 0)로 성공 여부를 안다. 같은 DB 파일을 연 연결 두 개로 이를 테스트했다(`test/audit.test.ts`)
- 기록 불변은 트리거로 DB 가 직접 거부한다(`BEFORE UPDATE/DELETE ... RAISE(ABORT)`). 애플리케이션 코드를 우회한 SQL 도 막힌다
- `node:sqlite` 는 Node 24.13 에서 실행할 때 `ExperimentalWarning` 을 낸다. API 가 바뀔 수 있다는 뜻이다
- 공식 문서: https://nodejs.org/api/sqlite.html

## 고른 것과 이유

C. 저장소를 받은 사람과 CI 가 DB 를 따로 설치하지 않고 바로 테스트할 수 있다. 서버 한 대 전제에서 조건부 변경·트랜잭션·트리거·CHECK 제약을 의존성 없이 모두 쓸 수 있다.

스키마는 PostgreSQL 로 옮길 때 바꿀 곳이 적게 짰다. 시각은 ISO 문자열, JSON 은 TEXT + `json_valid` 검사, 상태는 CHECK 제약이다. 옮길 때는 TEXT 를 `timestamptz`·`jsonb` 로, `AUTOINCREMENT` 를 `GENERATED ALWAYS AS IDENTITY` 로, 트리거 문법을 PL/pgSQL 로 바꾼다.

## 버린 대안과 그 대안의 가장 강한 장점

- **A. 메모리**: 가장 빠르고 코드가 짧다. 기록을 남길 필요가 없는 테스트 전용이라면 A 가 이긴다
- **B. JSON Lines**: 사람이 `cat` 으로 바로 읽고, 다른 도구로 흘려보내기 쉽다. 조건부 상태 변경 없이 추가만 한다면 B 가 이긴다
- **D. PostgreSQL**: 여러 서버가 같은 DB 를 쓰고, 행 잠금·권한 분리·복제가 된다. 앱 계정에서 감사 로그의 UPDATE·DELETE 권한을 회수(REVOKE)할 수 있어 트리거보다 불변 보장이 강하다. 서버를 두 대 이상 띄우거나 권한을 DB 계정으로 나눠야 한다면 D 가 이긴다

## 남은 문제

- **인증이 없다.** 승인자 이름(`operator`)은 요청 본문을 그대로 믿는다. 실제 운영이라면 로그인 사용자에서 가져와야 한다
- **트리거는 DB 파일을 가진 사람이 지울 수 있다.** 앱 코드나 실수로 고치는 것은 막지만, 파일 접근 권한이 있는 사람의 변조는 못 막는다
- **조치 실행은 시뮬레이션이다.** 승인하면 실행 기록만 남는다
- **`node:sqlite` 가 실험 기능이다.** API 가 바뀌면 `src/audit/store.ts` 를 고쳐야 한다

## 되돌리는 비용

`src/audit/store.ts` 한 파일이 SQL 을 전부 가진다. 다른 코드는 `AuditStore` 의 메서드(`append`·`events`·`propose`·`decide`·`markExecuted`)만 부른다. 저장소를 바꾸려면 이 클래스를 다시 구현하고 `test/audit.test.ts` 를 그대로 통과시키면 된다.
